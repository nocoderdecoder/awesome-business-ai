# Record adoption and outcomes honestly

Useful artifacts become more valuable when other people use and improve them. Keep evidence of that use separate from the fact that the artifacts exist.

## Evidence levels

| Evidence | What it can show | What it cannot establish by itself |
| --- | --- | --- |
| Commit history and dated files | What changed, when, and under which GitHub identity | Independent adoption or business benefit |
| Stars and forks | Public interest and repository reuse signals | Active use, unique users, quality or cost savings |
| Independent contributions | A contributor made a specific accepted improvement | Organization-wide deployment |
| A consented pilot record | A defined workflow was tested under recorded conditions | General performance outside those conditions |
| A documented outcome comparison | A measured change against a stated baseline | Causation if other variables changed |
| An independent, attributable user report | What that user says they used and observed | Outcomes beyond the reporter's experience |

## A minimal outcome record

Use the [outcome log](../templates/pilot-outcome-log.md). Retain:

- Workflow, artifact version or commit, dates, scope and accountable reviewer.
- Which data was synthetic, de-identified, approved for private use or cleared for publication.
- Sample count, case-selection method, baseline definition and comparison conditions.
- Quality failures, escalations, reviewer correction effort and rejected outputs.
- Task time, review time and full incremental cost; keep estimated and observed values separate.
- User permission for any public quote, identifiable attribution or shared example.

Do not publish private tickets, resumes, financial records or meeting transcripts. A redacted summary can describe the method without exposing the input. Publish quotes only with permission and retain their context.

## Time and cost calculations

For comparable tasks, report median task time and sample size. Count review and rework in AI-assisted time. Distinguish time capacity recovered from cash savings: freed minutes do not automatically reduce expenditure.

An illustrative calculation is:

```text
net time capacity = baseline task minutes - (AI workflow + review + rework minutes)
estimated capacity value = net time capacity / 60 × stated hourly cost assumption
net estimated value = estimated capacity value - incremental software and operating costs
```

These formulas provide a recording method, not a claim that this project produced savings. Include setup, training and maintenance when judging overall value. A pilot that improves speed while increasing material errors may be a failure.

## Recommended next work

1. Run one small, approved pilot using a playbook and retain passing and failing cases.
2. Ask actual users for specific feedback; record what changes because of it.
3. Improve the playbook and publish a consented, reproducible summary when available.
4. Accept independent contributions through ordinary review.
5. Review sources periodically and report outcomes using exact scope and dates.

Do not buy stars, solicit invented testimonials, count synthetic fixtures as customers, or label planned partnerships as established relationships.
